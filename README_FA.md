# اسکنر Kraken Futures — WaveTrend + OB/FVG نسخه ۱.۱.۱ عیب‌یابی‌شده

## مشخصات
- بازار فقط **Kraken Futures Perpetual**؛ قراردادهای قابل معامله با پیشوندهای `PF_` و `PI_`.
- هیچ داده Spot یا قرارداد تاریخ‌دار وارد اسکن نمی‌شود.
- تایم‌فریم فقط ۳۰ دقیقه و فقط کندل‌های بسته‌شده.
- اجرای زمان‌بندی‌شده GitHub Actions هر ۵ دقیقه؛ ارسال هشدار تلگرام؛ بدون ثبت سفارش.
- اندیکاتورها: `Wave Trend With Signals [ChuckBanger]` و `Order Blocks Zones with Signals [Uncle_the_shooter]`.
- سورس اصلی هر دو اندیکاتور در پوشه `sources` نگهداری شده است.

## منطق WaveTrend
پارامترهای سورس Pine حفظ شده‌اند: Channel Length=10، Average Length=21، OB2=53، OS2=-53، Laguerre=true و Gamma=0.02.
- BUY: کراس صعودی WT1 از WT2 درحالی‌که WT1 زیر -53 باشد.
- SELL: کراس نزولی WT1 از WT2 درحالی‌که WT1 بالای +53 باشد.
- واگرایی‌ها در تولید سیگنال دخالت ندارند.
- فقط سیگنال WT در سه کندل بسته‌شده اخیر برای ارسال بررسی می‌شود.

## منطق OB و FVG
پارامترهای سورس Pine حفظ شده‌اند: Pivot Length=10، Include Wicks=true، Candle Size Period=20، FVG multiplier=0.5، OB multiplier=0.1 و FVG Visible for=10.

نگاشت رنگ‌ها:
- **سبز OB و آبی FVG = BUY**.
- **قرمز OB و نارنجی FVG = SELL**.
- OB و FVG برای تأیید جهت معادل‌اند؛ برخورد به یکی از آن‌ها کافی است.

برخورد باکس با هم‌پوشانی محدوده High/Low کندل و محدوده قیمت باکس محاسبه می‌شود؛ لازم نیست Close داخل باکس باشد.

عمر باکس‌ها از قواعد خود Pine پیروی می‌کند:
- OB تا شکست معتبر با Close، پاکسازی ۵۰۰ کندل یا محدودیت ۵۰۰ باکس فعال می‌ماند.
- FVG تا شکست معتبر با Close، پاکسازی ۵۰۰ کندل یا محدودیت ۵۰۰ باکس فعال می‌ماند.
- پایان طول نمایش بصری FVG به‌تنهایی آن را غیرفعال نمی‌کند؛ باکس همچنان معتبر است تا اندیکاتور حذفش کند.
- اصلاح Pivot: کندل Pivot در زمان تأیید به‌اندازه Pivot Length عقب‌تر است؛ نگاشت کندل قدیمی‌تر و جدیدتر با offsetهای Pine کنترل شده و برخوردهای قیمتی مساوی به‌عنوان Pivot تکراری شمرده نمی‌شوند.

## تأیید نهایی سیگنال
1. رویداد WaveTrend باید در یکی از سه کندل بسته‌شده اخیر رخ داده باشد.
2. شش کندل بسته‌شده اخیر بررسی می‌شوند؛ کندل سیگنال نیز جزو این شش کندل است.
3. برای BUY باید حداقل یک برخورد با باکس فعال سبز OB یا آبی FVG وجود داشته باشد.
4. برای SELL باید حداقل یک برخورد با باکس فعال قرمز OB یا نارنجی FVG وجود داشته باشد.
5. **حتی یک برخورد با باکس مخالف در همین شش کندل، کل سیگنال را رد می‌کند؛ حتی اگر باکس هم‌جهت هم لمس شده باشد.**
6. نبود برخورد هم‌جهت به معنی عدم تأیید است؛ سیگنال در پنجره اخیر تا وقتی از سه کندل آخر خارج شود دوباره ارزیابی می‌شود.

## فیلتر نهایی بیت‌کوین
- آخرین سیگنال تأییدشده BTC در تایم‌فریم ۳۰ دقیقه جهت مرجع است.
- این فیلتر آخرین مرحله پیش از ارسال است.
- BTC BUY باشد فقط BUY آلت‌کوین‌ها ارسال می‌شود؛ BTC SELL باشد فقط SELL.
- سیگنال مخالف BTC حتی اگر تمام شروط WT و OB/FVG را داشته باشد حذف می‌شود.
- اگر جهت آخرین سیگنال تأییدشده BTC قابل تعیین نباشد، هیچ سیگنال آلت‌کوینی ارسال نمی‌شود.

## اولویت RSI(14)
RSI فقط اولویت سیگنال تأییدشده را مشخص می‌کند و در ساخت یا رد سیگنال نقشی ندارد:
- اولویت ۱: BUY با RSI **بالاتر از ۵۰**؛ SELL با RSI **پایین‌تر از ۵۰**.
- اولویت ۲: BUY با RSI برابر/پایین‌تر از ۵۰؛ SELL با RSI برابر/بالاتر از ۵۰.
- اولویت ۲ حذف نمی‌شود؛ بعد از اولویت ۱ ارسال می‌شود.

## گزارش تشخیصی
در خروجی هر اجرا، مرحله‌های زیر گزارش می‌شوند:
- تعداد سیگنال‌های خام BUY/SELL در WaveTrend.
- تعداد Pivotهای Low/High تأییدشده.
- تعداد ساخت و حذف OB/FVG و تعداد باکس‌های فعال صعودی/نزولی.
- تعداد سیگنال‌هایی که برخورد مخالف داشته‌اند و رد شده‌اند.
- تعداد سیگنال‌های فاقد برخورد هم‌جهت.
- تعداد سیگنال‌های تأییدشده قبل از فیلتر BTC، تعداد حذف‌شده توسط فیلتر BTC و تعداد نهایی قابل ارسال.
- خطاهای دریافت داده هر قرارداد جداگانه چاپ می‌شوند.

## فایل‌ها
- `scanner.py`: دریافت قراردادها و کندل‌های Kraken، فیلتر نهایی BTC، ارسال تلگرام و ثبت وضعیت هشدارها.
- `indicator_engine.py`: محاسبات WaveTrend، RSI، ساخت/ابطال/لمس باکس‌های OB/FVG و گزارش تشخیصی.
- `test_engine.py`: تست منطق اندیکاتورها، Pivot، پنجره شش کندلی، برخورد مخالف و ماندگاری FVG.
- `test_scanner_api.py`: تست قراردادهای Perpetual، حذف کندل باز و فیلتر نهایی BTC.
- `sources/`: سورس اصلی Pine هر دو اندیکاتور.
- `.github/workflows/scan.yml`: اجرای زمان‌بندی‌شده.
- `state.json`: جلوگیری از ارسال تکراری و مدیریت لغو هشدار.

## نصب و اجرا
1. ZIP را استخراج کنید و محتویات پوشه `Kraken_Derivatives_Scanner` را در ریشه مخزن GitHub جایگزین کنید.
2. مسیر `.github/workflows/scan.yml` باید حفظ شود.
3. در GitHub → Settings → Secrets and variables → Actions این دو Secret را تعریف کنید: `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID`.
4. در Settings → Actions → General مجوز Workflow برای `Read and write permissions` فعال باشد تا `state.json` ذخیره شود.
5. از تب Actions گزینه Run workflow را دستی اجرا کنید.

## آزمون و محدودیت
- آزمون آفلاین: `python -m unittest -v`
- نصب وابستگی‌ها: `pip install -r requirements.txt`
- آزمون‌های خودکار فعلی فقط منطق و API parsing را با داده‌های ساختگی/Mock بررسی می‌کنند؛ اتصال زنده Kraken و ارسال واقعی تلگرام از این محیط اجرا نشده است و باید با اجرای دستی Workflow بررسی شود.

## کنترل تازگی داده Kraken (اصلاح نسخه ۱.۱.۱)
- پاسخ کندل‌ها از نظر زمان آخرین کندل بسته‌شده بررسی می‌شود.
- اگر آخرین کندل بسته‌شده بیش از دو بازه ۳۰ دقیقه‌ای قدیمی باشد، پاسخ stale تلقی می‌شود و حداکثر سه بار دوباره درخواست می‌شود.
- پاسخ قدیمی هرگز به‌عنوان بازار فعلی اسکن نمی‌شود؛ در صورت تداوم، خطای `STALE_KRAKEN_CHART_DATA` در گزارش اجرا ثبت می‌شود.
- برای هر قرارداد، `DATA_OK` زمان آخرین کندل و میزان تأخیر را نشان می‌دهد؛ `DATA_STALE` تلاش مجدد را گزارش می‌کند.
