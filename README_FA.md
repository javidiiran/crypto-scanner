# اسکنر ۴ — Kraken Futures

اسکنر مستقل Python برای بازار Kraken Futures با تایم‌فریم ۱۵ دقیقه. داده‌ها از API عمومی Kraken دریافت می‌شوند؛ برای دریافت کندل و تیکر نیازی به API Key صرافی نیست.

## منطق نسخه اصلاح‌شده

### ۱) اندیکاتور اول: B-Xtrender

- فقط رنگ خط T3 با نام `B-Xtrender Color` مبنای سیگنال است؛ هیستوگرام‌ها و خط روند بلندمدت دخالتی ندارند.
- رنگ سبز یعنی جهت BUY و قرمز یعنی جهت SELL.
- برای BTC فقط تغییر رنگ روی آخرین کندل بسته‌شده لازم است: قرمز به سبز = BUY و سبز به قرمز = SELL.
- برای سایر ارزها، تغییر رنگ هم‌جهت باید در محدوده سه کندل بسته‌شده آخر رخ داده باشد؛ کندل تغییررنگ‌یافته باید سبز برای BUY یا قرمز برای SELL باشد.

### ۲) اندیکاتور دوم: Power Order Blocks [ChartPrime]

- BUY با باکس صعودی سبز و SELL با باکس نزولی بنفش/قرمز تأیید می‌شود.
- ایجاد باکس، حذف باکس‌های هم‌پوشان، حداکثر ۱۰ باکس در هر جهت و ابطال باکس مطابق منطق کد ارسالی پیاده‌سازی شده است.
- برای BTC، حداقل یک باکس فعال هم‌رنگ باید توسط یکی از چهار کندل بسته‌شده آخر لمس شده باشد.
- برای سایر ارزها، کندلی که در سه کندل اخیر تغییر رنگ هم‌جهت داده، باید با باکس فعال هم‌رنگ تماس/هم‌پوشانی داشته باشد.
- باکس فقط تا وقتی معتبر است که طبق منطق اندیکاتور ابطال نشده باشد. لمس باید پس از تشکیل باکس رخ داده باشد.

### ۳) بیت‌کوین فرمانده اسکنر

- ابتدا BTC بررسی می‌شود. به‌محض تغییر رنگ آخرین کندل بسته‌شده و تأیید Order Block، سیگنال BTC اعلام و اسکن سایر قراردادهای قابل معامله آغاز می‌شود.
- مجوز اسکن هم‌جهت برای چهار کندل ۱۵ دقیقه‌ای فعال است.
- ابتدای هر کندل بسته‌شده جدید، رنگ آخرین کندل BTC کنترل می‌شود. اگر خلاف جهت مجوز باشد، پنجره متوقف می‌شود تا سیگنال معتبر جدید BTC صادر شود.
- سیگنال BTC ابتدای پیام قرار می‌گیرد. اولین سیگنال فقط خودش را نشان می‌دهد؛ از سیگنال دوم به بعد، سیگنال فعلی، سیگنال قبلی و فاصله کندلی میان آن‌ها نیز نمایش داده می‌شود.

### ۴) جلوگیری از حذف بی‌دلیل سیگنال‌ها و گزارش تشخیصی

- دیگر نیازی به برابری دقیق زمان کندل ارز با BTC نیست؛ آخرین کندل بسته‌شده هر ارز بررسی می‌شود و اختلاف زمانی حداکثر یک کندل ۱۵ دقیقه‌ای پذیرفته می‌شود.
- هر قرارداد به‌صورت مستقل بررسی می‌شود. خطای دریافت داده یک ارز، اسکن بقیه را متوقف نمی‌کند.
- در گزارش GitHub Actions تعداد کل بازارها، تعداد سیگنال‌ها، تاریخچه ناکافی، نبود تغییر رنگ، نبود لمس باکس، کندل قدیمی، سیگنال تکراری و خطاهای دریافت/تحلیل جداگانه ثبت می‌شوند.
- هیچ سقف یک‌سیگنالی برای هر نوبت وجود ندارد.

### ۵) خروجی

- فقط سیگنال‌های هم‌جهت با BTC نمایش داده می‌شوند و BTC ابتدای پیام است.
- کنار هر سیگنال: درصد تغییر ۲۴ ساعته همان قرارداد، RSI همان قرارداد، RSI بیت‌کوین و رنگ دو کندل آخر B-Xtrender بیت‌کوین.
- سیگنال‌های سایر قراردادها بر اساس قدر مطلق درصد تغییر ۲۴ ساعته، از بیشترین به کمترین مرتب می‌شوند.
- فقط کندل‌های بسته‌شده استفاده می‌شوند.

## راه‌اندازی با GitHub Actions و تلگرام

1. یک Repository جدید در GitHub بسازید.
2. محتویات ZIP را در ریشه Repository بارگذاری و Commit کنید.
3. در `Settings → Secrets and variables → Actions` دو Repository Secret بسازید:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
4. در تب `Actions` اجرای workflow را فعال کنید.
5. Workflow هر پنج دقیقه اجرا می‌شود و `workflow_dispatch` امکان اجرای دستی را می‌دهد.
6. فایل `state.json` باید در Repository باقی بماند؛ Workflow تغییرات آن را commit/push می‌کند تا وضعیت بین اجراها حفظ شود.

## اجرای دستی روی کامپیوتر

```bash
python -m pip install -r requirements.txt
# متغیرهای TELEGRAM_BOT_TOKEN و TELEGRAM_CHAT_ID را تنظیم کنید
python scanner.py
```

## نکات مهم

- این پروژه سفارش خرید یا فروش ثبت نمی‌کند؛ فقط سیگنال می‌فرستد.
- هیچ کلید API خصوصی Kraken لازم نیست.
- RSI با دوره استاندارد ۱۴ محاسبه شده است.
- برای محاسبه تغییر ۲۴ ساعته از فیلد `change24h` تیکر Kraken Futures استفاده می‌شود.
- اجرای GitHub Actions هر پنج دقیقه است؛ بنابراین تشخیص پس از بسته‌شدن کندل ممکن است با تأخیر حداکثر حدود پنج دقیقه‌ای انجام شود.
- تست‌های محلی منطق اندیکاتورها و قوانین سیگنال در پوشه `tests` قرار دارند؛ اتصال زنده به API کراکن باید در اجرای GitHub Actions بررسی شود.
