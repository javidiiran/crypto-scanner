# اسکنر ۴ — Kraken Futures

اسکنر مستقل Python برای بازار Kraken Futures با تایم‌فریم ۱۵ دقیقه. داده‌ها از API عمومی Kraken دریافت می‌شوند؛ برای دریافت کندل و تیکر نیازی به API Key صرافی نیست.

## منطق ثبت‌شده

### ۱) اندیکاتور اول: B-Xtrender

- محاسبه بخش Short-Term طبق مقادیر پیش‌فرض اسکریپت ارسالی: EMAهای ۵ و ۲۰، سپس RSI با طول ۱۵ و T3 با طول ۵ و ضریب ۰٫۷.
- فقط رنگ خط T3 با نام `B-Xtrender Color` سیگنال می‌دهد؛ هیستوگرام‌ها و خط روند بلندمدت در سیگنال دخالت ندارند.
- الگوی BUY در سه کندل بسته‌شده آخر: قرمز، سبز، سبز.
- الگوی SELL در سه کندل بسته‌شده آخر: سبز، قرمز، قرمز.

### ۲) اندیکاتور دوم: Power Order Blocks [ChartPrime]

- BUY با باکس صعودی سبز تأیید می‌شود.
- SELL با باکس نزولی بنفش/قرمز تأیید می‌شود.
- ایجاد، حذف باکس هم‌پوشان، حداکثر ۱۰ باکس در هر جهت و ابطال باکس مطابق منطق کد ارسالی پیاده‌سازی شده است.
- برای تأیید، حداقل یک باکس فعال هم‌رنگ باید با محدوده قیمتی یکی از چهار کندل بسته‌شده آخر هم‌پوشانی داشته باشد.

### ۳) بیت‌کوین فرمانده اسکنر

- ابتدا فقط BTC بررسی می‌شود. سیگنال BTC تنها پس از الگوی سه‌کندلی B-Xtrender و تأیید Order Block معتبر است.
- سیگنال BTC ابتدای پیام اعلام می‌شود. اولین سیگنال فقط خودش را نشان می‌دهد؛ از سیگنال دوم به بعد، سیگنال فعلی، سیگنال قبلی و فاصله کندلی میان آن‌ها نیز نمایش داده می‌شود.
- پس از سیگنال معتبر BTC، اسکن هم‌جهت سایر قراردادهای قابل معامله برای پنجره چهار کندلی فعال می‌شود.
- ابتدای هر کندل بسته‌شده جدید، رنگ آخرین B-Xtrender بیت‌کوین کنترل می‌شود. اگر خلاف جهت مجوز باشد، اسکن متوقف می‌شود تا سیگنال معتبر جدید BTC صادر شود.
- پس از پایان چهار کندل، مجوز منقضی می‌شود.

### ۴) خروجی

- فقط سیگنال‌های هم‌جهت با BTC نمایش داده می‌شوند.
- BTC ابتدای گزارش قرار می‌گیرد.
- کنار هر سیگنال: درصد تغییر ۲۴ ساعته همان قرارداد، RSI همان قرارداد، RSI بیت‌کوین و رنگ دو کندل آخر B-Xtrender بیت‌کوین.
- سیگنال‌های سایر قراردادها بر اساس قدر مطلق درصد تغییر ۲۴ ساعته، نزولی مرتب می‌شوند.
- فقط کندل‌های بسته‌شده استفاده می‌شوند.

## راه‌اندازی با GitHub Actions و تلگرام

1. یک Repository جدید در GitHub بسازید.
2. محتویات ZIP را در ریشه Repository بارگذاری و Commit کنید.
3. در `Settings → Secrets and variables → Actions` دو Repository Secret بسازید:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
4. در تب `Actions` اجرای workflow را فعال کنید.
5. Workflow هر پنج دقیقه اجرا می‌شود و `workflow_dispatch` امکان اجرای دستی را می‌دهد.
6. فایل `state.json` باید در Repository باقی بماند؛ Workflow تغییرات آن را commit/push می‌کند تا وضعیت بین اجراها حفظ شود.

## اجرای دستی روی کامپیوتر

```bash
python -m pip install -r requirements.txt
# متغیرهای TELEGRAM_BOT_TOKEN و TELEGRAM_CHAT_ID را تنظیم کنید
python scanner.py
```

## نکات مهم

- این پروژه سفارش خرید یا فروش ثبت نمی‌کند؛ فقط سیگنال می‌فرستد.
- هیچ کلید API خصوصی Kraken لازم نیست.
- RSI با دوره استاندارد ۱۴ محاسبه شده است، چون طول RSI جداگانه‌ای در مشخصات تعیین نشده بود.
- برای محاسبه ۲۴ ساعته از فیلد `change24h` تیکر Kraken Futures استفاده می‌شود.
- در هر اجرای زمان‌بندی‌شده، فقط پس از تشکیل کندل ۱۵ دقیقه‌ای بسته‌شده جدید، اسکن انجام می‌شود؛ اجرای هر پنج دقیقه باعث تکرار هشدار روی یک کندل نمی‌شود.
- اگر API یا ساختار پاسخ Kraken تغییر کند، خطا در گزارش Actions ثبت می‌شود و اسکنر داده ناقص را به‌عنوان سیگنال معتبر گزارش نمی‌کند.
