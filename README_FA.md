# اسکنر آنلاین Binance Spot — SQZMOM + Dynamic Profile

## فایل‌ها
- `scanner.py` — دریافت همه جفت‌ارزهای فعال USDT در Binance Spot، بررسی کندل‌های بسته‌شده ۳۰ دقیقه‌ای و ارسال هشدار تلگرام.
- `ob_sqzmom_engine.py` — محاسبه SQZMOM و بازسازی محدوده‌های Peak/Trough از سورس Dynamic Profile ارسالی.
- `requirements.txt` — کتابخانه‌های موردنیاز.
- `.github/workflows/scan.yml` — اجرای خودکار هر ۵ دقیقه در GitHub Actions.
- `state.json` — جلوگیری از ارسال تکراری یک سیگنال برای یک کندل.

## منطق نهایی سیگنال

### BUY
1. هیستوگرام SQZMOM زیر صفر باشد.
2. میله هیستوگرام کندل بسته‌شده اخیر نسبت به میله قبلی کوتاه‌تر شده باشد.
3. حداقل یکی از ۵ کندل آخر، با محدوده یک ناحیه Trough (سبز/حمایت) تماس داشته باشد یا به آن نزدیک باشد.

### SELL
1. هیستوگرام SQZMOM بالای صفر باشد.
2. میله هیستوگرام کندل بسته‌شده اخیر نسبت به میله قبلی کوتاه‌تر شده باشد.
3. حداقل یکی از ۵ کندل آخر، با محدوده یک ناحیه Peak (قرمز/مقاومت) تماس داشته باشد یا به آن نزدیک باشد.

### فاصله کندل تا باکس
- هم‌پوشانی محدوده کندل و باکس: `0%` — TOUCH
- بیشتر از صفر تا `0.25%`: GOOD
- بیشتر از `0.25%` تا `0.50%`: WEAK؛ همچنان سیگنال معتبر است.
- بیشتر از `0.50%`: رد سیگنال.

فاصله از نزدیک‌ترین لبه باکس تا محدوده High/Low کندل محاسبه می‌شود؛ بنابراین لازم نیست فقط قیمت Close داخل باکس باشد.

## تنظیمات Dynamic Profile منتقل‌شده از سورس AlgoAlpha
- Lookback Mode: Fixed
- Lookback: 240 کندل
- Profile Resolution: 64
- Refresh Every: 5 کندل
- Volume Peaks: فعال، حداکثر 2
- Volume Troughs: فعال، حداکثر 1
- Peak Variant: Zones
- Trough Variant: Zones (برای اسکنر فعال شده تا باکس سبز BUY وجود داشته باشد)
- Zone Radius: 1 ردیف در هر طرف؛ باکس سه‌ردیفی
- Peak/Trough Detection: 7%
- Minimum Node Volume: 1%
- Smoothing Radius: 1
- Extend Previous Nodes: فعال
- Stop Extending On Break: فعال
- Level Expiry: 500 کندل
- Match Tolerance: 0.75 ردیف

Ranked Volume Rows و MFI در منطق نهایی استفاده نمی‌شوند.

## نصب در GitHub
1. فایل‌های داخل این پوشه را در ریشه مخزن GitHub قرار دهید؛ پوشه `.github/workflows` باید دقیقاً با همین مسیر حفظ شود.
2. در Settings → Secrets and variables → Actions دو Secret بسازید:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
3. از تب Actions، ورک‌فلو `Binance Spot SQZMOM Scanner` را با `Run workflow` یک‌بار دستی اجرا کنید.
4. اجرای زمان‌بندی‌شده هر ۵ دقیقه انجام می‌شود؛ چون فقط کندل‌های بسته‌شده ۳۰ دقیقه‌ای بررسی می‌شوند، هر اجرا الزاماً سیگنال جدیدی تولید نمی‌کند.
5. مجوز `contents: write` برای ذخیره `state.json` لازم است. در تنظیمات مخزن، در صورت نیاز به Actions اجازه نوشتن محتوا بدهید.

## نکات مهم
- بازار فقط Binance Spot و جفت‌های USDT است؛ هیچ Futures یا KCEX وجود ندارد.
- اسکنر همه جفت‌های فعال USDT را بررسی می‌کند و به رتبه CoinMarketCap یا تأیید BTC وابسته نیست.
- BUY/SELL صرفاً هشدار است. هیچ سفارشی ثبت نمی‌شود؛ SELL به معنی هشدار خروج/فروش دارایی Spot است، نه باز کردن Short.
- سیگنال هر جفت‌ارز برای هر کندل فقط یک‌بار ارسال می‌شود.
- محاسبه پروفایل در Python از منطق سورس Pine ارسالی بازسازی شده است. توزیع حجم بین ردیف‌ها در Pine به تابع `allocateVolume` و داده‌های کندل وابسته است؛ این نسخه از توزیع یکنواخت حجم در محدوده High/Low استفاده می‌کند، پس ممکن است مرز باکس‌ها در مواردی با TradingView دقیقاً یکسان نباشد.
- تست نحوی و تست محاسباتی محلی باید انجام شود؛ اتصال زنده Binance و تحویل واقعی پیام تلگرام فقط پس از اجرای Workflow در مخزن شما قابل تأیید است.


## رتبه‌بندی MFI از A تا D

MFI(14) فقط پس از تشکیل سیگنال معتبر SQZMOM + Dynamic Profile محاسبه می‌شود. این شاخص سیگنال را حذف نمی‌کند؛ همه سیگنال‌های معتبر، حتی رتبه D، به تلگرام ارسال می‌شوند. رتبه‌ها برای BUY و SELL جهت‌دار هستند:

| رتبه | BUY | SELL |
|---|---:|---:|
| A | MFI تا 20 | MFI از 80 به بالا |
| B | بیشتر از 20 تا 35 | 65 تا کمتر از 80 |
| C | بیشتر از 35 تا 50 | 50 تا کمتر از 65 |
| D | بیشتر از 50 | کمتر از 50 |

سیگنال‌ها ابتدا بر اساس رتبه MFI (A سپس B، C و D) مرتب می‌شوند. MFI در منطق ایجاد یا رد سیگنال دخالت ندارد.
