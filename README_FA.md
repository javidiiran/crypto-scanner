# اسکنر Kraken Futures — Wave Trend + Order Blocks/FVG 1.0

## مشخصات قطعی
- صرافی: فقط **Kraken Futures / Derivatives**.
- بازار: قراردادهای Perpetual قابل معامله با پیشوندهای `PF_` و `PI_`؛ Spot و قراردادهای تاریخ‌دار وارد نمی‌شوند.
- تایم‌فریم: ۳۰ دقیقه.
- فقط کندل‌های بسته‌شده بررسی می‌شوند.
- اجرا با GitHub Actions هر ۵ دقیقه؛ هشدار پس از بسته‌شدن کندل و مشاهده شرط تأیید ممکن است.
- خروجی تلگرام؛ هیچ سفارشی ثبت نمی‌شود.

## دو اندیکاتور و منطق اصلی

### ۱) Wave Trend With Signals [ChuckBanger]
سورس Pine v4 ارسالی کاربر مبناست. پارامترهای پیش‌فرض عیناً حفظ شده‌اند:
- Channel Length = 10
- Average Length = 21
- Over Bought Level 2 = 53
- Over Sold Level 2 = -53
- Apply Laguerre Smoothing = true
- Laguerre Gamma = 0.02
- Wave Trend 2 = SMA چهار دوره‌ای Wave Trend 1

فقط دو سیگنال اصلی اندیکاتور استفاده می‌شوند:
- BUY: کراس صعودی WT1 از WT2 و WT1 کمتر از -53 (`signal1`).
- SELL: کراس نزولی WT1 از WT2 و WT1 بیشتر از +53 (`signal2`).
- واگرایی‌ها در اسکن دخالت ندارند.

### ۲) Order Blocks Zones with Signals [Uncle_the_shooter]
منطق ساخت و ابطال باکس‌ها از سورس Pine v6 ارسالی کاربر پورت شده است:
- Pivot Length = 10
- Include Wicks in OB = true
- Candle Size Period = 20
- FVG Size Multiplier = 0.5
- OB Size Multiplier = 0.1
- FVG Visible for = 10 bars
- OB عمر پاک‌سازی = 500 کندل

نگاشت جهت باکس‌ها:
- OB سبز = صعودی؛ OB قرمز = نزولی.
- FVG آبی = صعودی (معادل سبز برای تأیید خرید).
- FVG نارنجی = نزولی (معادل قرمز برای تأیید فروش).

تماس باکس با برخورد محدوده High/Low کندل به محدوده باکس سنجیده می‌شود؛ بسته‌شدن Close داخل باکس لازم نیست. باکس باید در همان کندل تماس فعال و قابل مشاهده باشد.

## پنجره تأیید
برای هر سیگنال Wave Trend:
- چهار کندل بسته‌شده قبل از کندل سیگنال بررسی می‌شوند.
- دو کندل بسته‌شده بعد از کندل سیگنال نیز فرصت تأیید هستند.
- خود کندل سیگنال جزو شش کندل بررسی تماس نیست.
- BUY فقط با تماس با OB سبز یا FVG آبی تأیید می‌شود.
- SELL فقط با تماس با OB قرمز یا FVG نارنجی تأیید می‌شود.
- اگر حتی یک تماس با باکس مخالف در هر نقطه پنجره رخ دهد، کل سیگنال رد می‌شود؛ حتی اگر باکس هم‌رنگ هم لمس شده باشد.
- اگر تا پایان دو کندل بعدی تماس هم‌رنگ رخ ندهد، سیگنال منقضی و حذف می‌شود.
- به محض مشاهده تماس هم‌رنگ و نبود تماس مخالف در بخش سپری‌شده پنجره، هشدار ارسال می‌شود. اگر در ادامه پنجره باکس مخالف لمس شود، یک پیام جداگانه لغو سیگنال ارسال می‌شود تا هشدار قبلی بی‌اعتبار اعلام شود.

## اولویت‌بندی RSI(14)
RSI وایلدر روی قیمت بسته‌شدن کندلی محاسبه می‌شود که سیگنال در آن قابل اعلام می‌شود: اگر لمس هم‌رنگ در چهار کندل قبل رخ داده باشد، RSI کندل سیگنال؛ اگر تأیید در یکی از دو کندل بعد رخ دهد، RSI همان کندل تأیید:
- اولویت ۱: BUY با RSI >= 50 و SELL با RSI < 50.
- اولویت ۲: سایر سیگنال‌های تأییدشده.
- اولویت ۲ حذف نمی‌شود؛ فقط پس از اولویت ۱ ارسال می‌شود.

## اطلاعات هر هشدار
- نماد و جهت BUY/SELL
- تایم‌فریم و قیمت کندل سیگنال
- RSI همان ارز هنگام تأیید سیگنال
- گروه اولویت RSI
- نوع باکس تأییدکننده: OB، FVG یا هر دو
- زمان سیگنال Wave Trend
- آخرین سیگنال تأییدشده BTC و زمان آن
- RSI بیت‌کوین هنگام آخرین سیگنال و RSI فعلی BTC روی آخرین کندل بسته‌شده ۳۰ دقیقه‌ای

BTC به‌عنوان مرجع اطلاعاتی گزارش می‌شود؛ جهت BTC فیلتر ورود برای سایر ارزها نیست و هیچ استثنای تأیید اندیکاتور برای BTC اعمال نشده است.

## جلوگیری از تکرار
- کلید یکتا: نماد + تایم‌فریم + زمان کندل سیگنال + جهت.
- هر سیگنال فقط یک بار ارسال می‌شود.
- وضعیت ارسال و لغو در `state.json` ذخیره می‌شود.
- اگر بعد از هشدار، برخورد مخالف در پنجره باقی‌مانده رخ دهد، فقط پیام لغو یک‌بار ارسال می‌شود.

## فایل‌ها
- `scanner.py`: اتصال عمومی Kraken Futures، دریافت Perpetualها و کندل‌های بسته، ارسال تلگرام، ذخیره تاریخچه هشدار.
- `indicator_engine.py`: پیاده‌سازی Wave Trend، RSI، ساخت و ابطال OB/FVG و منطق تأیید.
- `test_engine.py`: آزمون سیگنال‌ها، پنجره تأیید، برخورد مخالف، انقضا و اولویت RSI.
- `test_scanner_api.py`: آزمون فهرست قراردادها، حذف کندل باز و انتخاب آخرین سیگنال BTC.
- `.github/workflows/scan.yml`: اجرای زمان‌بندی‌شده هر ۵ دقیقه.
- `state.json`: جلوگیری از تکرار هشدار و پیام لغو.

## نصب و راه‌اندازی
1. ZIP را استخراج کنید.
2. تمام محتویات پوشه `Kraken_Derivatives_Scanner` را در ریشه مخزن GitHub جایگزین کنید؛ مسیر `.github/workflows/scan.yml` حفظ شود.
3. در GitHub → Settings → Secrets and variables → Actions این دو Secret را نگه دارید/تعریف کنید:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
4. در Settings → Actions → General، مجوز Workflow برای `Read and write permissions` فعال باشد تا `state.json` ذخیره شود.
5. در Actions، ابتدا `Run workflow` را دستی اجرا کنید.

## تست و محدودیت
- تست آفلاین: `python -m unittest -v`
- وابستگی‌ها: `pip install -r requirements.txt`
- اتصال زنده Kraken و ارسال واقعی تلگرام از محیط ساخت قابل تأیید نیست؛ اجرای Workflow دستی برای آزمون نهایی ارتباط لازم است.
- زمان‌بندی هر ۵ دقیقه است؛ داده و سیگنال فقط از کندل‌های بسته‌شده استفاده می‌کنند.
