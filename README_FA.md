# اسکنر Kraken Futures — نسخه ۱.۲.۰

## مشخصات اصلی
- بازار فقط **Kraken Futures Perpetual** با نمادهای `PF_` و `PI_`؛ داده Spot و قرارداد تاریخ‌دار وارد اسکن نمی‌شود.
- تایم‌فریم ۳۰ دقیقه و فقط کندل‌های بسته‌شده.
- اجرای زمان‌بندی‌شده GitHub Actions هر ۵ دقیقه و ارسال هشدار به تلگرام؛ اسکنر هیچ سفارشی ثبت نمی‌کند.
- اندیکاتورها: `Wave Trend With Signals [ChuckBanger]` و `Order Blocks Zones with Signals [Uncle_the_shooter]`.
- سورس اصلی Pine هر دو اندیکاتور در پوشه `sources` نگهداری شده است.

## منطق WaveTrend
پارامترهای سورس Pine حفظ شده‌اند: Channel Length=10، Average Length=21، OB2=53، OS2=-53، Laguerre=true و Gamma=0.02.
- BUY: کراس صعودی WT1 از WT2 درحالی‌که WT1 زیر -53 باشد.
- SELL: کراس نزولی WT1 از WT2 درحالی‌که WT1 بالای +53 باشد.
- واگرایی‌ها در تولید سیگنال دخالت ندارند.
- برای آلت‌کوین‌ها، رویداد WT باید در یکی از سه کندل بسته‌شده اخیر باشد؛ این شرط نسخه قبلی حفظ شده است.

## منطق OB و FVG
پارامترهای سورس Pine حفظ شده‌اند: Pivot Length=10، Include Wicks=true، Candle Size Period=20، FVG multiplier=0.5، OB multiplier=0.1 و FVG Visible for=10.

نگاشت رنگ‌ها:
- **سبز OB و آبی FVG = BUY**.
- **قرمز OB و نارنجی FVG = SELL**.
- برخورد به یکی از OB یا FVG هم‌جهت کافی است.
- برخورد باکس با هم‌پوشانی محدوده High/Low کندل و محدوده قیمت باکس محاسبه می‌شود؛ لازم نیست Close داخل باکس باشد.

عمر باکس‌ها از قواعد اندیکاتور Pine پیروی می‌کند:
- OB تا شکست معتبر با Close، پاکسازی ۵۰۰ کندل یا محدودیت ۵۰۰ باکس فعال می‌ماند.
- FVG تا شکست معتبر با Close، پاکسازی ۵۰۰ کندل یا محدودیت ۵۰۰ باکس فعال می‌ماند.
- پایان طول نمایش بصری FVG به‌تنهایی آن را غیرفعال نمی‌کند.
- نگاشت Pivot و offsetهای Pine حفظ شده‌اند.

## پنجره تأیید هفت‌کندلی
- هفت کندل بسته‌شده اخیر بررسی می‌شوند؛ کندل سیگنال هم جزو این هفت کندل است.
- برای BUY حداقل یک برخورد با باکس فعال سبز OB یا آبی FVG لازم است.
- برای SELL حداقل یک برخورد با باکس فعال قرمز OB یا نارنجی FVG لازم است.
- **حتی یک برخورد با باکس مخالف در همین پنجره هفت‌کندلی، کل سیگنال را رد می‌کند؛ حتی اگر باکس هم‌جهت نیز لمس شده باشد.**
- نبود برخورد هم‌جهت به معنی عدم تأیید است.

## جهت بیت‌کوین — منطق توافق‌شده
۱. **اولین جهت BTC:** در اولین اجرای اسکنر، آخرین سیگنال WaveTrend بیت‌کوین در تایم‌فریم ۳۰ دقیقه جهت اولیه را به‌تنهایی تعیین می‌کند. برای این مرحله هیچ تأیید OB/FVG لازم نیست.

۲. **تغییر جهت‌های بعدی:** پس از تعیین جهت اولیه، هر تغییر جهت فقط زمانی پذیرفته می‌شود که یک سیگنال WaveTrend جدید و مخالف جهت فعلی، با برخورد به باکس هم‌رنگ OB یا FVG در پنجره هفت کندل بسته‌شده اخیر تأیید شود.

۳. سیگنال مخالفِ بدون تأیید، جهت فعلی BTC را تغییر نمی‌دهد. تأیید باید با باکس هم‌جهت باشد؛ وجود برخورد باکس مخالف باعث رد کاندیدا می‌شود.

۴. جهت BTC، زمان سیگنال، RSI و منبع تعیین جهت (WaveTrend اولیه یا تأیید OB/FVG) در `state.json` ذخیره می‌شوند تا در اجرای بعدی از نو مقداردهی نشوند.

۵. فقط سیگنال‌های آلت‌کوین هم‌جهت با آخرین جهت ذخیره‌شده BTC اجازه ارسال دارند. اگر هنوز هیچ سیگنال WT برای BTC وجود نداشته باشد، هشدار آلت‌کوین ارسال نمی‌شود.

## RSI و اولویت هشدار
- RSI با روش Wilder و دوره ۱۴ محاسبه می‌شود.
- کنار هر هشدار، RSI ارز هنگام تأیید و RSI فعلی آن ارز در آخرین کندل بسته‌شده نمایش داده می‌شود.
- آخرین جهت BTC، زمان سیگنال BTC، RSI بیت‌کوین هنگام سیگنال و RSI فعلی BTC نیز در همان هشدار درج می‌شود.
- اولویت ۱: BUY با RSI بالاتر از ۵۰ یا SELL با RSI پایین‌تر از ۵۰.
- اولویت ۲: BUY با RSI برابر/پایین‌تر از ۵۰ یا SELL با RSI برابر/بالاتر از ۵۰.
- RSI فقط اولویت را مشخص می‌کند؛ سیگنال را ایجاد یا حذف نمی‌کند. اولویت ۲ نیز حذف نمی‌شود.

## دریافت کندل و رفع خطای STALE_KRAKEN_CHART_DATA
- مسیر رسمی Kraken Futures Charts API استفاده می‌شود: `/api/charts/v1/trade/{symbol}/30m`.
- پارامترهای `from` و `to` برحسب ثانیه Unix هستند؛ مقدار `time` هر کندل برحسب میلی‌ثانیه Unix است.
- زمان `time` زمان شروع کندل است؛ برای سنجش بسته‌شدن، ۳۰ دقیقه به آن اضافه می‌شود.
- ابتدا درخواست بازه‌دار ارسال می‌شود. اگر پاسخ قدیمی باشد، اسکنر درخواست آخرین کندل‌ها با `count` و سپس درخواست بدون فیلتر بازه را نیز امتحان می‌کند.
- این روند تا سه دور تکرار می‌شود. اگر آخرین کندل بسته‌شده همچنان بیش از دو بازه ۳۰ دقیقه‌ای قدیمی باشد، اسکن متوقف می‌شود؛ داده کهنه هرگز وارد محاسبه سیگنال نمی‌شود.
- پیام‌های `DATA_OK`، `DATA_STALE` و `DATA_EMPTY` روش دریافت و تازگی داده را در گزارش مشخص می‌کنند.

## فایل‌ها
- `scanner.py`: دریافت قراردادها و کندل‌های Kraken، حفظ جهت BTC، فیلتر آلت‌کوین‌ها، هشدار تلگرام و ذخیره state.
- `indicator_engine.py`: محاسبات WaveTrend، RSI، ساخت/ابطال/لمس باکس‌های OB/FVG.
- `test_engine.py`: آزمون منطق اندیکاتورها، پنجره هفت‌کندلی، برخورد مخالف و ماندگاری FVG.
- `test_scanner_api.py`: آزمون API parsing، داده کهنه، جهت اولیه BTC، تغییر جهت تأییدشده، ذخیره state و متن هشدار RSI.
- `sources/`: سورس اصلی Pine دو اندیکاتور.
- `.github/workflows/scan.yml`: اجرای خودکار هر پنج دقیقه.
- `state.json`: تاریخچه هشدارها و جهت پایدار BTC.

## نصب و اجرا در GitHub
۱. ZIP را استخراج کنید و **محتویات پوشه** `Kraken_Derivatives_Scanner` را در ریشه مخزن GitHub جایگزین کنید؛ پوشه `.github/workflows` نیز باید در ریشه مخزن قرار بگیرد. اگر `state.json` فعلی مخزن سابقه هشدارهای ارسال‌شده دارد، همان فایل فعلی را نگه دارید؛ نسخه جدید ساختار قدیمی آن را خودکار ارتقا می‌دهد و سابقه جلوگیری از هشدار تکراری حفظ می‌شود.
۲. در GitHub → Settings → Secrets and variables → Actions این دو Secret را بسازید:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
۳. در Settings → Actions → General، گزینه Workflow permissions را روی `Read and write permissions` قرار دهید تا `state.json` ذخیره شود.
۴. از تب Actions، Workflow را با `Run workflow` اجرا کنید. اجرای زمان‌بندی‌شده بعد از آن هر پنج دقیقه انجام می‌شود.

- وابستگی‌ها: `pip install -r requirements.txt`
